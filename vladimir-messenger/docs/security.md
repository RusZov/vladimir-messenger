# Безопасность и шифрование

## Обзор

Владимир использует современные криптографические примитивы для обеспечения конфиденциальности и целостности сообщений.

## Криптографические алгоритмы

### 1. X25519 (Elliptic Curve Diffie-Hellman)

**Назначение:** Обмен ключами между пользователями

**Параметры:**
- Кривая: Curve25519
- Размер ключа: 256 бит (32 байта)
- Безопасность: ~128 бит

**Пример генерации ключей:**
```python
from cryptography.hazmat.primitives.asymmetric.x25519 import X25519PrivateKey

private_key = X25519PrivateKey.generate()
public_key = private_key.public_key()
```

### 2. ChaCha20-Poly1305

**Назначение:**Authenticated encryption сообщений

**Параметры:**
- Шифр: ChaCha20 (256-bit key)
- MAC: Poly1305 (128-bit tag)
- Nonce: 96 бит (12 байт)
- Режим: AEAD (Authenticated Encryption with Associated Data)

**Преимущества перед AES-GCM:**
- Устойчивость к timing attacks
- Высокая производительность на устройствах без AES-NI
- Простота реализации

### 3. HKDF-SHA256

**Назначение:** Деривация ключей из общего секрета

**Параметры:**
- Hash function: SHA-256
- Output length: 32 байта
- Salt: None (или публичный контекст)
- Info: "vladimir-messenger-v1"

**Процесс:**
```python
from cryptography.hazmat.primitives.kdf.hkdf import HKDF
from cryptography.hazmat.primitives import hashes

hkdf = HKDF(
    algorithm=hashes.SHA256(),
    length=32,
    salt=None,
    info=b"vladimir-messenger-v1",
)
derived_key = hkdf.derive(shared_secret)
```

## Процесс установления безопасного соединения

### Шаг 1: Генерация ключей

При первом запуске каждый узел генерирует постоянную пару ключей:
```
Private Key: [секретно, хранится локально]
Public Key:  [открыто, передаётся контактам]
```

### Шаг 2: Обмен публичными ключами

Пользователи обмениваются публичными ключами через внеполосный канал:
- QR-код
- Личная встреча
- Доверенный мессенджер

**Важно:** Это единственный момент, когда требуется доверие. После этого работает TOFU (Trust On First Use).

### Шаг 3: Вычисление общего секрета

Обе стороны вычисляют общий секрет независимо:
```python
# Сторона A
shared_secret_A = private_key_A.exchange(public_key_B)

# Сторона B
shared_secret_B = private_key_B.exchange(public_key_A)

# shared_secret_A == shared_secret_B
```

### Шаг 4: Деривация ключа шифрования

Из общего секрета деривируется ключ для ChaCha20:
```python
encryption_key = HKDF(shared_secret, info=b"vladimir-messenger-v1")
```

### Шаг 5: Шифрование сообщения

Для каждого сообщения:
1. Генерируется уникальный nonce
2. Сообщение шифруется через ChaCha20-Poly1305
3. Отправляется `{nonce, ciphertext}`

```python
from cryptography.hazmat.primitives.ciphers.aead import ChaCha20Poly1305
import os

nonce = os.urandom(12)
chacha = ChaCha20Poly1305(encryption_key)
ciphertext = chacha.encrypt(nonce, plaintext, None)
```

## Модель безопасности

### Конфиденциальность

| Атакующий | Защита |
|-----------|--------|
| Пассивный наблюдатель | Сквозное шифрование |
| Активный MITM | Проверка публичных ключей |
| Компрометация сервера | Нет центрального сервера |
| Компрометация узла | Локальное хранение ключей |

### Целостность

- Poly1305 MAC гарантирует целостность каждого сообщения
- Любая модификация ciphertext будет обнаружена при расшифровке

### Аутентичность

- TOFU модель: первый полученный ключ считается доверенным
- Пользователь должен верифицировать ключи внеполосно

## Уникальные идентификаторы

### Nonce Management

Каждое сообщение использует уникальный nonce:
- Генерируется через `os.urandom(12)`
- Никогда не повторяется с одним ключом
- Передаётся в открытом виде вместе с ciphertext

**Важно:** Повторное использование nonce с тем же ключом компрометирует безопасность ChaCha20.

### Message IDs

- UUID v4 для каждого сообщения
- Используется для deduplication
- Не является криптографически защищённым

## Хранение ключей

### Приватные ключи

Хранятся только в памяти процесса:
```python
class CryptoManager:
    def __init__(self):
        self.private_key = X25519PrivateKey.generate()
        # Не сохраняется на диск
```

**Рекомендация для production:**
- Использовать OS keychain (Keychain/Keystore)
- Шифрование ключа паролем пользователя
- Hardware security modules (HSM) для серверов

### Публичные ключи контактов

Сохраняются в памяти приложения:
```python
self.contact_keys = {
    "alice": X25519PublicKey(...),
    "bob": X25519PublicKey(...),
}
```

**Рекомендация для production:**
- Постоянное хранилище (SQLite с шифрованием)
- Резервное копирование с защитой

## Известные ограничения

### 1. TOFU уязвимость

Первое соединение не верифицировано. Злоумышленник может провести MITM атаку при первоначальном обмене ключами.

**Митигация:**
- Обязательная проверка ключей через QR-код
- Использование нескольких каналов для верификации

### 2. Отсутствие Perfect Forward Secrecy

Постоянные ключи означают, что компрометация приватного ключа позволяет расшифровать все прошлые сообщения (если они были перехвачены).

**Улучшение для future версии:**
- Double Ratchet алгоритм (как в Signal)
- Эфемерные ключи для каждой сессии

### 3. Metadata leakage

P2P транспорт раскрывает метаданные:
- IP адреса участников
- Время активности
- Размер сообщений

**Митигация:**
- Использование Tor режима скрывает IP
- Padding сообщений до фиксированного размера

## Best Practices

### Для пользователей

1. ✅ Всегда проверяйте публичные ключи контактов
2. ✅ Используйте QR-коды для первичного обмена
3. ✅ Регулярно делайте backup ключей
4. ❌ Не передавайте ключи через незащищённые каналы

### Для разработчиков

1. ✅ Используйте проверенные криптобиблиотеки
2. ✅ Никогда не реализуйте свои криптоалгоритмы
3. ✅ Обрабатывайте ошибки расшифровки безопасно
4. ❌ Не логируйте приватные ключи или общие секреты
