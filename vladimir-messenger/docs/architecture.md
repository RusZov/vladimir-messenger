# Архитектура Владимира Мессенджера

## Обзор

Владимир — это гибридный P2P-мессенджер с поддержкой работы через интернет (Tor), локальную сеть и Bluetooth LE mesh.

## Модули

### 1. crypto_module.py

**Назначение:** Сквозное шифрование сообщений

**Алгоритмы:**
- **X25519** — обмен ключами по алгоритму Диффи-Хеллмана
- **ChaCha20-Poly1305** —authenticated encryption с дополнительным кодом аутентификации
- **HKDF-SHA256** — деривация ключей из общего секрета

**Процесс шифрования:**
1. Генерация постоянного приватного ключа при первом запуске
2. Обмен публичными ключами между пользователями (TOFU — Trust On First Use)
3. Вычисление общего секрета через DH обмен
4. Деривация ключа шифрования через HKDF
5. Шифрование сообщения с уникальным nonce

### 2. p2p_transport.py

**Назначение:** Управление сетевыми соединениями

**Режимы работы:**

#### Интернет (Tor)
- Создание ephemeral hidden service (.onion)
- Использование stem для управления Tor
- Трафик маршрутизируется через сеть Tor

#### Локальная сеть (LAN)
- UDP широковещание на порт 5000 для discovery
- Автоматическое обнаружение узлов в Wi-Fi сети
- TCP соединения на порт 5001 для передачи данных
- Формат discovery-сообщения:
```json
{
    "type": "discovery",
    "peer_id": "abc123",
    "public_key": "base64...",
    "tcp_port": 5001,
    "timestamp": 1234567890
}
```

#### Mesh ретрансляция
- Очередь сообщений для офлайн-получателей
- TTL сообщений: 5 минут
- Автоматическая отправка при появлении получателя

### 3. ble_mesh.py

**Назначение:** Сверхближняя связь через Bluetooth LE

**Характеристики:**
- Дальность: до 10 метров
- Mesh-ретрансляция через промежуточные узлы
- Максимум 3 прыжка (hops)
- Кастомный GATT сервис с UUID `0000vlad-0000-1000-8000-00805f9b34fb`

**Процесс работы:**
1. Сканирование устройств с нашим сервисом
2. Подключение к устройству
3. Запись сообщения в TX characteristic
4. Чтение ответов из RX characteristic

### 4. app.py

**Назначение:** Flask веб-приложение и координация компонентов

**API Endpoints:**
- `GET /api/status` — статус приложения
- `GET/POST /api/contacts` — управление контактами
- `GET/POST /api/messages` — отправка/получение сообщений
- `POST /api/messages/broadcast` — групповая рассылка
- `POST /api/files` — отправка файлов
- `GET /api/peers` — список обнаруженных пиров

## Поток данных

### Отправка сообщения

```
Пользователь → Веб-интерфейс → Flask API → Crypto (шифрование) 
                                           ↓
                                    P2P Transport → Получатель
                                           ↓
                                    Mesh Queue (если офлайн)
```

### Получение сообщения

```
Отправитель → P2P Transport → Crypto (расшифровка) → Веб-интерфейс
```

## Безопасность

### Модель угроз

| Угроза | Защита |
|--------|--------|
| Перехват трафика | Сквозное шифрование |
| MITM атака | TOFU + проверка ключей |
| Анализ метаданных | Tor (в режиме интернета) |
| Компрометация устройства | Локальное хранение ключей |

### Trust On First Use (TOFU)

При первом контакте с пользователем его публичный ключ сохраняется и используется для всех последующих сессий. Пользователь должен проверить ключ через внеполосный канал (QR-код, личная встреча).

## Масштабируемость

### Ограничения прототипа

- Хранение сообщений: только в памяти (до перезапуска)
- Количество контактов: не ограничено
- Размер файла: до 10 МБ
- Mesh очередь: 5 минут TTL

### Возможные улучшения

- Постоянное хранилище (SQLite/PostgreSQL)
- Индексация сообщений для поиска
- Групповые чаты с управлением участниками
- Голосовые/видео звонки через WebRTC
